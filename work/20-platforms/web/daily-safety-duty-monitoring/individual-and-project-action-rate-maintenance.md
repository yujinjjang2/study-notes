# 개인·현장 조치율 조회 유지보수 기준

## 대상

- 화면: 일일안전당직자모니터링
- Mapper: `MontInqCompanyPersonInChargeMonitoringSql.xml`
- 개인 조회: `selectIndivActRateList`
- 현장 조회: `selectProjActRateList`
- 점검자 기준 참고: `SfasRegCompanyDailySafetyPersonInChargeSql.xml`의 `selectPicList`

## 요구사항과 처리 방향

개인 조치율은 점검 건수가 있는 사용자만이 아니라, 조회 회차·현장에 속한 점검 대상 사용자 전체를 보여야 한다. 점검 대상 건수와 추가위험 건수가 없는 사용자는 각각 `0건`, 조치율 `0%`로 표시한다.

이를 위해 개인 조회에는 기존 `TR_PIC`과 별도로 `TR_ALL_PIC` CTE를 둔다. `TR_PIC`은 일자별 점검 항목을 배분하고 실제 점검 건수를 계산하는 기존 역할을 유지한다. `TR_ALL_PIC`은 최종 개인 목록의 기준 집합만 담당한다. 두 역할을 분리하면 기존 항목 배분 규칙을 바꾸지 않으면서 0건 사용자를 표시할 수 있다.

## 전체 점검자 기준

`TR_ALL_PIC`은 일일안전당직자등록 `selectPicList`의 사용자 선별 기준을 회차별로 적용한다.

| 모니터링 대상 | 구분 | 포함 조건 |
| --- | --- | --- |
| 중점점검 | 기업 | 활성 사용자(`TCC_EMPLOYE.USE_TAG = 'T'`)이며 현장근무 사용자(`TCC_USER_PROJ_CODE.PROJ_WORK_TF = 'T'`) 또는 해당 회차에 이미 점검자로 등록된 사용자 |
| 중점점검 | 협력사 | 활성 사용자이며 현장근무·일일안전점검 가능 사용자(`DLY_SAF_PIC_PSBL_TF = 'T'`) 또는 해당 회차에 이미 점검자로 등록된 사용자 |
| 추가위험 | 기업 | 활성 사용자이며 현장근무 사용자 또는 해당 회차에 이미 점검자로 등록된 사용자 |
| 공통 | 해당 범위 | 조회한 현장·회차·사용자명·구분 조건을 적용 |

협력사 범위는 `TCC_PROJ_LINK`의 `LINK_SUB_TAG = 'F'`와 `MON_TGT_SECT_CODE = 'EMPHS'` 조건을 함께 사용한다. 따라서 추가위험(`ADD`) 조회에는 협력사 범위를 만들지 않고 기업만 표시한다. 현장직책과 직위 표시는 각각 `TCC_USER_PROJ_DR`, `VPJ_CODE_LIST`을 기존 개인 조회와 같은 방식으로 연결한다.

## 개인 조치율 집계 구조

1. `TR_PIC`, `TR_CHK_LIST`는 기존처럼 실제 점검자와 점검 항목을 이용해 중점점검 건수를 집계한다.
2. `TR_ALL_PIC`을 최종 결과의 기준 목록으로 둔다.
3. 중점점검 집계 결과는 회사·현장·기업/협력사·항목·구분·사용자 키로 `TR_ALL_PIC`에 외부 조인한다.
4. 추가위험 조회는 기업 기준 목록만 사용하고, 추가위험 집계는 사용자 키로 외부 조인한다.
5. 집계값이 없으면 건수는 `Nvl(..., 0)`으로 표시한다.
6. 조치율은 대상 건수가 0이면 `0`을 반환하고, 대상 건수가 있을 때만 기존 `SF_SafeDivide` 계산을 적용한다.

`SF_SafeDivide`의 세 번째 인수는 0 분모에 대한 대체값이다. 개인 화면의 요구사항은 명시적으로 `0%`이므로, 함수의 대체값에만 의존하지 않고 대상 건수 0 여부를 먼저 분기해야 한다.

## 현장 조치율은 현재 집계 로직 유지

`selectProjActRateList`는 실제 점검 대상 건수와 실시 건수를 현장·회차 단위로 합산해 조치율을 계산한다. 따라서 전체 점검자 목록을 붙이지 않고 현재의 실제 건수 집계 로직을 유지한다.

개인 조회에 0건 사용자를 추가해도 현장 합계에는 영향을 주지 않는다. 0건 사용자는 합계의 분자와 분모를 모두 증가시키지 않기 때문이다. 반대로 현장 조회까지 전체 사용자 목록을 기준으로 바꾸면 다대다 조인으로 합계가 중복될 위험이 있고, 현장 요약 목적에도 맞지 않는다.

단, 다음 요구가 추가되면 현장 조회도 별도 변경한다.

- 점검 대상이 하나도 없는 현장·회차도 결과 행으로 보여야 하는 경우
- 현장별 전체 점검자 수, 0건 사용자 수 같은 인원 현황을 같이 보여야 하는 경우

위 경우에는 `TR_TIME`을 기준 집합으로 두고 실제 집계를 외부 조인한다. 그 전에는 현장 조치율에 전체 사용자 기준 CTE를 재사용하지 않는다. 필요하다면 분모 합계가 0일 때만 조치율을 `0%`로 반환하도록 분기한다.

## 수정·검증 체크리스트

- 기업 현장근무 사용자, 협력사 점검 가능 사용자, 이미 점검자로 지정된 사용자가 모두 조회되는지 확인한다.
- 점검 건수 없는 사용자가 한 행으로 조회되고 중점점검·추가위험 건수와 조치율이 모두 0인지 확인한다.
- 점검 건수가 있는 사용자의 기존 건수와 조치율이 바뀌지 않는지 비교한다.
- 중점점검에서는 기업·협력사, 추가위험에서는 기업만 `TR_ALL_PIC` 기준 목록에 포함되는지 확인한다.
- 사용자명과 구분 필터가 `TR_ALL_PIC` 기준 목록에도 적용되는지 확인한다.
- 동일한 사용자·항목이 중복 행으로 늘어나지 않는지 확인한다.
- 현장 조치율의 중점점검·추가위험 합계가 개인 조치율의 실제 건수 합계와 일관되는지 확인한다.
- 운영 데이터로 반영하기 전 동일 조건에서 결과 건수, 실행계획, Buffers, Starts, 경과 시간을 비교한다.
