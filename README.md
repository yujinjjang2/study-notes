# Study Notes

회사에서 수행한 업무와 개인 학습에서 얻은 내용을, 나중의 내가 다시 이해하고 이어갈 수 있는 형태로 기록하는 저장소입니다.

## 목표

- 업무와 학습 과정에서 배운 내용을 짧고 명확한 Markdown 문서로 남긴다.
- 배경, 시도한 방법, 결과, 다음 행동을 기록하여 맥락을 잃지 않는다.
- 작은 기록도 꾸준히 커밋하여 변화 이력을 GitHub에 보관한다.
- 장기적으로는 Codex와의 대화를 요약해 Markdown 문서로 만드는 개인 스킬을 구현한다.

## 기록 원칙

- 공개해도 안전한 내용만 기록한다. 회사의 비공개 정보, 고객 정보, 인증 정보, 내부 코드와 문서는 올리지 않는다.
- 업무 기록은 문제의 일반화된 맥락, 배운 점, 재현 가능한 절차 위주로 작성한다.
- 한 문서에는 하나의 주제를 담고, 제목과 날짜를 분명히 적는다.
- 완벽하게 정리될 때까지 미루지 않고, 초안도 먼저 남긴 뒤 필요하면 보완한다.

## 폴더 구조

```text
study-notes/
├── work/                       # 공개 가능한 업무 회고·기술 정리
│   ├── 00-guides/              # 업무 노트 작성 안내와 템플릿
│   ├── 10-features/            # 기능 단위 분석
│   ├── 20-platforms/           # 플랫폼 공통 분석
│   │   ├── web/                # 기존 WEB 분석 문서
│   │   ├── mobile/             # Android, iOS 관련 분석
│   │   ├── api/                # API 공통 규칙과 호출 흐름
│   │   └── report/             # 리포트 관련 분석
│   ├── 30-external-services/   # 외부 API, 인증, 웹훅 연동
│   ├── 40-client-maintenance/  # 고객사 운영 문의·장애·설정 유지보수
│   └── 90-archive/             # 종료·이관된 참고 문서
├── learning/                   # 개인 학습 노트
├── conversations/              # Codex 대화에서 정리한 기록
└── README.md
```

업무 노트의 세부 분류와 작성 규칙은 [work/README.md](work/README.md)에서 관리한다. 분석에 필요한 회사 소스는 참고만 하며, 정리 결과는 이 저장소에 공개 가능한 형태로 작성한다.

## 시작 방법

새 기록을 작성한 뒤 아래 명령으로 GitHub에 올립니다.

```powershell
git add .
git commit -m "Add study note: <주제>"
git push
```

## 핸드오프

### 현재 상태

- GitHub 원격 저장소: `yujinjjang2/study-notes`
- 기본 브랜치: `main`
- 이 README는 저장소 운영 목적과 기록 규칙을 정의하는 첫 문서다.

### 다음 작업

1. 새 업무 노트는 `work/README.md`의 분류 규칙에 맞는 폴더에 작성한다.
2. 첫 학습 또는 업무 회고 문서를 Markdown으로 작성한다.
3. 대화 요약 스킬의 입력 형식, 요약 템플릿, 파일명 규칙을 정한다.
4. 스킬을 구현한 뒤 실제 대화 한 건으로 결과를 검증한다.

### 대화 요약 스킬 초안

- 입력: 대화 원문 또는 선택된 대화 범위
- 출력: 날짜, 주제, 핵심 결정, 실행한 작업, 결과, 다음 할 일을 포함한 Markdown 문서
- 저장 위치: `conversations/YYYY-MM-DD-주제.md`
- 안전 장치: API 키·비밀번호·개인정보·회사 기밀을 문서에 남기기 전에 제거하도록 한다.
